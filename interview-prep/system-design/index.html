How a session runs

  1. Warm-up re-quiz Three to five questions pulled from earlier topics’ drill archives — yesterday’s topic, last week’s, and one older one at random.
  2. Micro-lesson One idea. Small enough to teach in a few minutes.
  3. Drill ladder Many questions per rung, and no climbing until the rung is clean: recognition → recall → produce → translate (Mermaid ↔ Java) → apply → critique → flip the requirement → explain why. The flip rung holds the code still and changes a requirement, so the same design gets the opposite verdict.
  4. Compile-and-run checkpoint Wherever runtime behaviour is the actual lesson, the code gets compiled with JDK 17 and run.
  5. Notes get written The topic page gains today’s concept, diagram, snippet, runnable file and the full drill archive with answers.

The mastery gate

All four, or the topic does not move:

Per topic

A gate that fails twice is a signal the step was too big. The step gets split and re-drilled smaller — that is the system working, not you failing.

Java 17 — JAVA_HOME is already JDK 17; note that java on PATH resolves to an older JDK 11, so compile commands pin 17 explicitly.

Diagrams render from a vendored assets/mermaid.min.js, so these pages work offline with no build step and no server. Progress of record lives in PROGRESS.md; the checkboxes here are a convenience that your browser remembers.
